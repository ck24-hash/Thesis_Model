# Repository structure

How the `Thesis_Model` repository is organised, what each folder contains and how the pieces depend on each other.

## Tree

```
Thesis_Model/
├── README.md                  quick start, input format, main assumptions (copied into the thesis)
├── CLAUDE.md                  project context and conventions for Claude Code
├── pyproject.toml             package definition (ghmodel), pytest settings
├── requirements.txt           dependencies (unpinned)
├── requirements-lock.txt      exact versions that passed the tests
├── .gitignore                 ignores .venv, caches, results/*, data/*.xlsx (except *EXAMPLE*)
│
├── src/ghmodel/               THE MODEL (all logic lives here)
│   ├── __init__.py            exports Params, column mappings; silences PyPSA/linopy logging
│   ├── config.py              Params (all parameters + defaults), Excel column mapping, country defaults
│   ├── data.py                read + check the Excel input (hourly or daily), dummy data generator
│   ├── sizing.py              automatic sizes (None -> value), annuity, hourly marginal costs
│   ├── blocks.py              reusable building blocks (one function per system component)
│   ├── scenarios/
│   │   ├── baseline.py        Baseline: NG boiler + thermal storage + grid import
│   │   └── s1_chp.py          Scenario 1: CHP + backup boiler + thermal storage + grid import/export
│   ├── workflow.py            solve() and run_scenario(): build -> solve -> results in one call
│   ├── results.py             hourly results table, balance checks, KPI table (same layout for all scenarios)
│   ├── analysis.py            storage value, financial analysis (payback, NPV, IRR), scenario comparison
│   └── plots.py               all figures (adapt automatically to the components of the scenario)
│
├── notebooks/                 THIN NOTEBOOKS: set parameters, call ghmodel, show results
│   ├── 01_baseline.ipynb
│   └── 02_s1_chp.ipynb
│
├── tests/                     pytest checks (run: .venv\Scripts\python.exe -m pytest -q)
│   ├── test_baseline.py       balances, constraints, input handling, storage value, finance (Baseline)
│   └── test_s1_chp.py         CHP conversion, export revenue, CHP priority, finance vs Baseline (S1)
│
├── data/                      INPUTS (git-ignored except the *EXAMPLE* files)
│   ├── baseline_input_data_EXAMPLE_dummy.xlsx   dummy hourly input for the Baseline
│   ├── s1_input_data_EXAMPLE_dummy.xlsx         same + elec_export_price_EUR_per_MWh column (S1)
│   └── *_input_data.xlsx      your real data (created as dummy by the notebooks if missing)
│
├── results/                   OUTPUTS, regenerated by the notebooks (git-ignored, only .gitkeep tracked)
│   ├── baseline/              baseline_results.xlsx, baseline_network.nc, figures/*.png
│   └── s1_chp/                s1_chp_results.xlsx, s1_chp_network.nc, figures/*.png
│
├── scripts/                   STAND-ALONE HELPER SCRIPTS (not imported by the model)
│   └── kew_extract_demand.py  extracts daily heat, electricity and CO2 demand from a KasEnergieWijzer
│                              'GetResults' JSON response -> CSV + plots (source of daily demand data)
│
└── docs/                      DOCUMENTATION
    ├── Scenarios.png          the scenario figure (Baseline, S1-S4): reference for every flow
    ├── scenario_report.pdf    3-page report: scenarios, inputs/outputs, constraints, limits, upgrades
    ├── blocks/                one page per model block (parameters, inputs, outputs, constraints)
    └── repository/            this page
```

## How the pieces fit together

```
data/*.xlsx ──> data.load_inputs ──> hourly DataFrame (MW, t/h, EUR/MWh)
                                          │
config.Params ──> sizing.resolve_sizes ───┤  sizes, annualised costs, hourly marginal costs
                                          ▼
              scenarios/<name>.build ──> PyPSA network made of blocks.add_* functions
                                          │
                     workflow.solve ──> HiGHS (LP) + blocks.add_custom_constraints
                                          │
     results.extract_results / check_balances / summarise ──> Results (r, monthly, summary, k)
                                          │
               analysis.* (storage value, finance, comparison)   plots.* (figures)   results.export_results
```

`workflow.run_scenario(build, data, P)` does sizing, building, solving and results in one call; the notebooks show
each step separately so that intermediate tables can be inspected.

## Rules of the repository
- **Logic in `src/ghmodel/`, notebooks only call it.** This keeps scenarios comparable and git diffs readable.
- **New scenario** = new blocks in `blocks.py` (+ a page in `docs/blocks/`), a `scenarios/<name>.py` with
  `build(data, P, sizes)`, a test file and a notebook. The KPI table keeps the same rows for every scenario.
- **Every modelling assumption** is listed in `README.md` ("Main assumptions") and flagged in the code comments.
  Flows not drawn in `docs/Scenarios.png` (heat dump, CO2 vent, slack) are assumptions.
- **Placeholders**: parameter values marked `[placeholder]` in `config.py` are not sourced yet.
- **Data**: real input data is never committed (`data/*.xlsx` is git-ignored).
- **Units**: MW, MWh, t CO2, EUR everywhere inside the model; conversions happen only in `data.py`.
